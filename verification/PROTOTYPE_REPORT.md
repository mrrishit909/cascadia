## Open risks/defects

- **D1 (P1): cross-control interruption silently undoes a confirmed removal.** In `src/app/state.tsx`, `removedBus` is written only by the `solved` action, so while a removal is pending the state (latest or closure) still says `removedBus: null`. The requested-but-unresolved removal is recorded nowhere. If the slider moves during that window, the capacity request omits the removed bus and supersedes it. Reproduced in production with a 1.5 s WASM delay (`verification/review_scripts/race_reverse.mjs 1500`). This is plausible on first load because the WASM is 1.2 MB gzipped. The slider is not disabled during `solving` (the Remove controls are). Reading from a ref would NOT fix this, because the ref would also hold `null`. Fix direction: make the `solving` action record the requested scenario (`removedBus`/`lineCapacity`) and build later requests from that pending intent, or disable the slider while `solve === 'solving'`.
- **D2 (P1): the infeasible state still exposes confident zeros in the network view.** `f1142bb` fixed the two text panels only. In `src/visualization/NetworkView.tsx:24,33`, every line's accessible name reads e.g. "Line 9, slack, 0.00 of 8.00 MW" (from `flows[l.idx] ?? 0`; the flows object is empty when infeasible). All lines render grey (meaning no flow), all buses render as served, and the map has no infeasible indication. Same class as audit finding #6.
- **D3 (P2): inconsistent bus numbering.** The committed e2e screenshot shows "Bus 2 unavailable" (1-based name) next to "Live HiGHS Worker solve: bus 1 removed" (0-based idx). Diagnostics list islands by 0-based idx while the map labels are 1-based.
- **D4 (P2):** The SVG `aria-label` is always "IEEE case30 network, baseline dispatch", even after a solve.
- **D5 (P2):** The infeasible diagnostic renders twice as `role="alert"` (once in each panel), so screen readers announce it twice.
- **D6 (P2):** A slider move inside the 250 ms debounce window is silently discarded if a removal lands first (the slider resyncs to 1.00x). Reproduced 3/3 with slider-first ordering, and also with removal-first ordering and no injected delay (`race_reverse.mjs 0`: cap-factor back to 1.00x, line 9 not altered). So under normal conditions, one of two near-simultaneous inputs is dropped in either order. Losing the *removal* (D1) needs only a slow first solve.
- **R1:** The e2e covers one bus (idx 1), where all shed is load at the removed bus. No e2e covers economic (LP) shed, a no-generation island, CAS-INT-005, or the infeasible diagnostic in the browser; those are covered only by jsdom unit tests and this review's ad-hoc probes.
- **R2:** CAS-DATA-001 license TODO is still open (the underlying UW/IEEE benchmark license text was not located).
- **R3:** Lint is not clean (5 warnings).
